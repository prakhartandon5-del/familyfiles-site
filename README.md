# familyfiles — landing page

The public site for [familyfiles](https://familyfiles.vercel.app), a private
family information organizer sold as a one-time $19 download.

A single static landing page plus privacy, terms and contact. No framework, no
runtime JavaScript, no third-party scripts.

## Build

```bash
node build.mjs      # -> dist/
npm run dev         # build and serve on :4321
```

`build.mjs` assembles each page from `src/` with a shared head and footer and
substitutes configuration at build time, so the shipped HTML works with
JavaScript disabled.

## Configuration

All of it lives in `site.config.json`, overridable by environment variables in
Vercel:

| Key | Env var | Notes |
| --- | --- | --- |
| `checkoutUrl` | `CHECKOUT_URL` | The payment link. **While empty, every CTA points at `/#get`** rather than a dead URL. Set it once and all five CTAs follow. |
| `siteUrl` | `SITE_URL` | Used for canonical URLs, Open Graph and the sitemap. |
| `supportEmail` | `SUPPORT_EMAIL` | Shown on the contact, privacy and terms pages. |
| `price` | — | Displayed price string. |

## Assets

Product screenshots in `public/assets/` are captured from the real application
(desktop and phone variants, served via `<picture>`) and are regenerated by
`scripts/build-site-assets.mjs` in the application repo. `og.png` and the touch
icon come from `scripts/make-site-og.mjs`.

## Verifying

`scripts/verify-site.mjs` in the application repo checks the built site: every
section, every link, all four phone widths plus desktop, horizontal overflow,
metadata, console errors, and that it still renders with JavaScript disabled.
It accepts a URL to run the same checks against a deployment.
